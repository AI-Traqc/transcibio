Kapitel 01 — Was ist Transcibio?

Vom Audio
zur Antwort.

Transcibio ist ein Audio-Assistent, der vollständig auf Ihrem Computer läuft. Sie geben ihm eine Aufnahme — ein Meeting, ein Interview, eine Vorlesung, eine Sprachnotiz — und er macht daraus ein lesbares Transkript.

Anschließend können Sie mit dem Transkript chatten: Fragen stellen, nach Themen suchen, fundierte Antworten bekommen. Transcibio schlägt sogar Folgeaktionen vor — E-Mail-Entwürfe, To-Do-Listen, Notizen — und kann Antworten per Text-to-Speech vorlesen.

Kerngedanke
Nichts verlässt Ihren Rechner. Audio, Transkripte, Konversationen — alles bleibt lokal. Keine Cloud, keine Drittanbieter, keine Daten-Uploads.
Kapitel 02 — Motivation

Transcibio löst zwei Probleme auf einmal.

01 / Privatsphäre

Das Privacy-Problem.

Die meisten Transkriptions-Tools senden Audio an entfernte Server. Bei sensiblen Inhalten — juristische Beratung, medizinische Gespräche, Finanz-Reviews, vertrauliche Interviews, interne Meetings — wird das zum echten Risiko.

Transcibio entfernt diese Vertrauensanforderung vollständig. Jede Komponente — Speech-to-Text, Speaker-ID, LLM, TTS — läuft auf Ihrer Hardware.

02 / Produktivität

Das Produktivitäts-Problem.

Wichtige Gespräche finden täglich statt — aber die Erkenntnisse daraus gehen oft verloren. Notizen sind unzuverlässig, Re-Listening kostet Zeit, das Durchsuchen stundenlanger Aufnahmen ist unpraktisch.

Transcibio macht aufgezeichnete Gespräche durchsuchbar und interaktiv. Statt erneut zuzuhören: fragen, antworten lassen — mit Verweis auf den exakten Moment im Transkript.

Kapitel 04 — Anwendung

Der Weg — vom Audio zur Aktion.

Fünf einfache Schritte. Jeder einzelne läuft komplett auf Ihrem Rechner.

01

Aufnehmen oder hochladen

MP3, WAV, WebM und weitere Formate — direkt im Browser oder per Upload.

02

Lokal transkribieren

STT mit drei Stufen: fast · balanced · quality.

03

Transkript prüfen

Mit Timestamps und Speaker-Labels. Jede Korrektur erzeugt eine neue Revision.

04

Mit dem Text chatten

Fragen tippen oder sprechen. Antworten zitieren die jeweilige Quellstelle.

05

Aktionen ausführen

E-Mails, Tasks, Notizen — Vorschlag prüfen, bestätigen, exportieren.

Hands-free möglich Sprechen Sie einfach drauflos — der Sprachmodus hört zu, antwortet laut und hört wieder zu. Eine fortlaufende, freihändige Konversation (siehe Kapitel 08).
Kapitel 05 — Architektur

Drei Schichten, ein Rechner.

Frontend kommuniziert mit Backend, Backend orchestriert die lokalen AI-Provider. Alle drei Ebenen laufen auf Ihrer Maschine.

Layer 01 Frontend
React + TypeScript Vite shadcn/ui Sidebar Chat View Transcript Editor Voice Recorder Silero VAD Web Audio
↓   REST API · SSE · WebSocket (Sprachmodus)   ↓
Layer 02 Backend
FastAPI · Python SQLite Transcription Orchestrator Chat Orchestrator Action Orchestrator TTS Orchestrator Background Jobs
↓   localhost · Subprocess Calls   ↓
Layer 03 Local AI Provider
Faster-Whisper · STT pyannote.audio · Diarization Ollama / LM Studio · LLM Piper · TTS (DE) Kokoro · TTS (EN) FFmpeg · Audio

Jeder Provider ist optional. Fehlt einer, degradiert das System graceful — keine Komplettausfälle.

Kapitel 07 — Wie funktioniert das?

Zwei Pipelines, klar getrennt.

A Transcription Pipeline

Audio rein, strukturiertes Transkript raus.

01 · Storage

Audio prüfen

FFmpeg

Format validieren, Metadaten extrahieren (Dauer, Sample Rate, Kanäle).

02 · STT

Audio → Text

Faster-Whisper

Segmente mit Timestamps und Wort-genauen Zeit­markierungen.

03 · Diarization

Wer spricht wann?

pyannote.audio

Speaker-Segmente: A: 0:00–0:15, B: 0:15–0:42 …

04 · Assembly

Zusammenführen

Backend

Text + Speaker-Labels werden zu einer Transkript-Revision in SQLite.

B Chat Pipeline · Retrieval-Augmented Generation (RAG)

Frage rein, fundierte Antwort mit Zitaten raus.

01 · Retrieval

Relevante Stellen finden

Sparse Lexical

Top-K Segmente per TF-Cosine-Similarity. Kein Embedding-Modell nötig.

02 · Prompt

Kontext bauen

Backend

Segmente + Frage + Zitier-Anweisung werden zum Prompt zusammengesetzt.

03 · LLM

Antwort generieren

Ollama / LM Studio

Das Modell antwortet — gegrundet auf den gefundenen Segmenten, mit Zitaten.

04 · Citations

Quellen verlinken

Backend

Segment-Refs werden zu Timestamps + Speaker-Namen + Zitaten gemappt.

Blended Grounding: Liegt ein Transkript vor, zitiert jede Antwort die exakte Stelle. Ohne Transkript antwortet Transcibio als allgemeiner lokaler Assistent — fundiert statt erfunden.

Kapitel 08 — Sprachmodus

Freihändig sprechen — in Echtzeit.

Der Sprachmodus macht aus dem einmaligen Voice Command eine fortlaufende, freihändige Konversation: Sie sprechen, Transcibio antwortet laut und hört sofort wieder zu — eine Schleife, bis Sie ihn ausschalten.

01

Zuhören

Eine browser-seitige Silero VAD erkennt offline, wann Sie sprechen.

02

Transkribieren

Die Äußerung wird lokal mit Faster-Whisper zu Text — Sprache fest an die Engine gekoppelt.

03

Tokens streamen

Das LLM streamt die Antwort live über den WebSocket /voice-turn.

04

Schneiden & sprechen

Der SentenceChunker bildet Sätze; Piper/Kokoro synthetisieren sie als rohes PCM.

05

Lückenlos abspielen

Web Audio reiht die Sätze nahtlos aneinander — dann zurück zu Schritt 01. ↺

A · Barge-in

Einfach unterbrechen.

Sprechen Sie, während der Assistent redet, bricht die Wiedergabe sofort ab und Ihr neuer Beitrag wird aufgenommen — wie bei einem echten Gespräch.

B · Sprach-Lock

Engine bestimmt die Sprache.

Die Antwortsprache ist fest an die TTS-Engine gekoppelt: Piper spricht Deutsch (de_DE-thorsten-high), Kokoro Englisch. So driftet das Modell nie in eine unaussprechbare Sprache.

C · Latenz & lokal

~2,3 s bis zum ersten Ton.

Warm dominiert das lokale LLM die Latenz — nicht das TTS. VAD-Modell und TTS-Stimmen liegen lokal; zur Laufzeit wird nichts aus dem Netz geladen.

Tipp: Kopfhörer empfohlen — über Lautsprecher kann die eigene Stimme des Assistenten das Mikrofon erreichen und Barge-in selbst auslösen.

Kapitel 09 — Weitere Funktionen

Drei Bonus-Features für den Workflow.

A · Voice Commands

Per Stimme statt Tastatur.

Sprechen Sie Ihre Frage. Transcibio nimmt im Browser auf, transkribiert lokal mit Faster-Whisper und sendet als Chat-Nachricht.

  • Review-Modus: erst prüfen, dann senden
  • Auto-Send-Modus: direkt absenden
  • Basis für den fortlaufenden Sprachmodus (Kapitel 08)
B · Action Proposals

Aus Gespräch wird Tat.

Erkennt der Assistent etwas Handlungs­würdiges, schlägt er eine konkrete Folgeaktion vor — mit Vorschau in der Chat-View.

  • E-Mail-Entwürfe
  • Task-Listen / To-Dos
  • Notizen und Dokument-Exports
  • Erst nach Ihrer Bestätigung exportiert
C · Text-to-Speech

Antworten als Audio.

Die Antworten des Assistenten werden lokal vorgelesen — mit Piper (Deutsch) oder Kokoro (Englisch), komplett offline.

  • Optional aktivierbar
  • Funktioniert auch ohne — Chat läuft normal weiter
  • Piper als Subprocess · Kokoro in-process (ONNX)
Kapitel 10 — Für Forschende & Entwickler:innen

Vier Design-Entscheidungen, die zählen.

Pattern 01

Orchestrator-Pattern

Jede Hauptfunktion (Transcription, Chat, Actions, TTS) hat ihren eigenen Orchestrator — koordiniert kleinere Komponenten. Workflow-Logik bleibt zentral, einzelne Bausteine bleiben einfach und testbar.

Pattern 02

Protocol-basierte Provider

STT, LLM, TTS, Diarization sind Python-Protocol-Klassen. Faster-Whisper gegen anderes STT-Modell tauschen? Interface implementieren — fertig. Kein anderer Code muss geändert werden.

Pattern 03

Immutable Transkript-Revisions

Jede Änderung (initiale Transkription, manueller Edit, Speaker-Rename, LLM-Korrektur) erzeugt eine neue Revision — die alte bleibt erhalten. Vollständige Edit-Historie, Undo jederzeit möglich.

Pattern 04

Background Job Queue

Lange Operationen (Transkription, Chat-Reply) laufen in einem Worker-Thread. Job-Status wird in SQLite gespeichert, das Frontend bekommt Fortschritts-Updates per Server-Sent Events.

Graceful Degradation: Fehlt ein Provider, fällt das System auf einen einfacheren Modus zurück und protokolliert das als Warning — statt komplett zu scheitern. Transcibio läuft auch mit minimalem Setup.
